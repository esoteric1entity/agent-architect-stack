Security

agent-shield v0.2.1 alpha

A defensive overlay for AI agents.

What It Does

agent-shield checks what your AI agent is about to run, and where it is about to write. It blocks actions that match its list of dangerous patterns, lets you decide on those that match its list of risky ones, and lets everything else through. Wired as a hook, it keeps a record of what it decided. It includes a check you can run on a skill or plugin folder before you install it.

Checks shell commands, and where file writes and edits go, before they run. In Claude Code, the PowerShell tool, file reads, web fetches, notebook edits and other tools are not checked.

  • A 3-tier scan you run on a new skill, plus a 5-layer manual review guide
  • 4-layer input sanitization (structural, content, encoding, context)
  • Bash + write guards
  • Audit: a log that can be checked for edited lines

What It Doesn't Do

Known limits in v0.2.1. Some are part of the design, and for some a fix is planned. We update this list with each release.

  • Design limit It is a filter that works from a list of known risky patterns, not a sandbox, so anything it doesn't recognise passes through.
  • It does not stop prompt injection.
  • Partial fix planned An agent can switch the guard off without a warning.
  • Partial fix planned On Windows, Claude Code often runs commands through its PowerShell tool, which agent-shield does not check.
Show the Other 10 Known Limits
  • Partial fix planned In v0.2.1 a shell command can still write to files the file-edit guard protects, such as its own files, Claude Code settings, SSH keys and .env files.
  • It logs every command and file path it checks, word for word, including any password or token typed into them.
  • On Windows, some ways of writing a path can get past the file-edit guard.
  • Fix planned If the guard can't start or takes more than five seconds, Claude Code lets the action go ahead without it, except on Windows without Git Bash, where recent versions block it.
  • Partial fix planned In OpenClaw, some calls go unchecked, and calls go ahead if the guard can't run in time or your OpenClaw version skips plugin checks.
  • Partial fix planned The add-on check doesn't read every file in an add-on, so it can miss a risky one.
  • If two sessions write to the log at once, a record can be lost or the check can raise a false alarm.
  • Design limit The log shows if a line was edited, but someone with access to the file can still delete recent lines or rewrite it.
  • Partial fix planned A Claude Code mod can act without agent-shield checking it, and in sessions without managed settings it can approve what agent-shield blocked.
  • Network egress control and scheduled log rotation are designed but not built.

For stronger protection, leave Claude Code's permission prompts on, and run work you don't trust in a sandbox or container.

Where It's Headed

The goal: a small guard you can read line by line, with no cloud service and no dependencies, that does two jobs well: checking skills, plugins and MCP servers before you install them, and limiting what a prompt injection can make your agent do.

Next: close or clearly disclose every known way to switch it off quietly, and back every claim on this page with a test. Then the two jobs, and support for more agent harnesses, starting with Hermes Agent and OpenCode.

Harnesses & Agent Platforms

Which One Runs Your Agent? Most of these run against local models and need no subscription; where one does not, its card says so.

Anthropic's terminal-native coding agent, and the harness most of this stack is built against.

COMMERCIAL

MITLOCAL

NVIDIA’s hardened wrapper around OpenClaw — it sandboxes the agent inside OpenShell, and will run Hermes as an alternate agent.

A terminal pair programmer that edits files in your git repository and commits each change separately, using a repository map instead of loading the whole codebase.

A local-first agent, CLI and desktop, reaching models and tools through MCP extensions and able to run entirely offline. Donated by Block to the Agentic AI Foundation, so no longer vendor-owned.

A provider-agnostic terminal agent — the option if you want a daily driver that isn't tied to one vendor's model.

MITLOCAL

An open terminal agent forked from Google’s Gemini CLI and developed independently since. Tuned for Qwen models, but it will run against other endpoints.

Rotate anything it could have seen.

02 ORCHESTRATE

Multi-Step & Multi-Agent

One Agent Turn Is Easy. What Runs A Hundred Of Them, In Order, Without Losing State? This is the most crowded corner of the field, and most builders do not need this layer until they do.

Graph & Contract-First

LangGraph

Graph-based orchestration where durable execution, streaming, human-in-the-loop and memory are runtime guarantees rather than things you bolt on. The default pick if you want explicit control over state.

MITSELF-HOST

PydanticAI

Type contracts rather than a graph: you define what each step must return and the framework holds the model to it. The lighter option if a graph DSL feels like ceremony.

MITSELF-HOST

LlamaIndex Workflows

Event-driven orchestration from the LlamaIndex team, at its best when the pipeline is document- and retrieval-heavy rather than general-purpose.

MIT
Role-Based & Interoperability-First

CrewAI

Models a workflow as a crew of role-playing agents with assigned tasks. The most widely adopted framework in this style, and the fastest way to see a multi-agent system working.

MIT

AG2

The community continuation of AutoGen, with native MCP and agent-to-agent protocol support — the pick when you care most about talking to other systems.

Apache-2.0MCP CLIENT

A TypeScript-native agent framework, for when the rest of the project is already JavaScript and a Python orchestrator would be the odd one out.

03 RUN

Models & Inference

Where Does The Model Actually Execute? Local first; hosted where it earns its place.

Local Engines & Runtimes

Ollama

The shortest path from nothing to a model running on your own machine, and increasingly an agent CLI in its own right. If you would rather click than type, the desktop apps that do the same job are on Interact. If you already run it, UMS can point its optional memory add-ons at a local Ollama model for embeddings — one of two local options, and nothing in the stack installs it for you.

MITLOCAL

llama.cpp

The engine underneath most local LLM tooling. Its mixture-of-experts offload options let a large model run on one consumer GPU plus system RAM.

MITLOCAL

KTransformers

Runs large mixture-of-experts models on a single consumer GPU plus system RAM by keeping the routed experts on the CPU. Backed by a published systems paper.

Apache-2.0LOCAL

ik_llama.cpp

A llama.cpp fork for hybrid CPU/GPU inference of large mixture-of-experts models. One maintainer, CPU and CUDA only — a specialist tool, not a replacement.

MITLOCAL

MLX

Apple's array framework for on-device training and inference, and the software half of what makes a Mac worth buying for this. No longer Apple-only — it now ships a CUDA backend that installs on Linux.

MITLOCAL

llama.cpp quantize & imatrix

The tooling that converts full-precision weights to GGUF at a chosen bit depth, with importance-matrix calibration to decide what to keep sharp. This is how a model that would not fit ends up fitting.

MITLOCAL

04 METAL

Hardware & Vendor Platforms

What Are You Running It On? Entries name the platform, not one vendor's box — the same silicon usually ships in several.

Platforms — the silicon, and everyone who ships a box around it

NVIDIA GB10 (DGX Spark platform)

A desk-side class of machine with unified memory, for running and fine-tuning large models locally without a rack. NVIDIA's own DGX Spark is one of eight systems on this chip — Acer, ASUS, Dell, GIGABYTE, HP, Lenovo and MSI ship the rest.The silicon is identical across all of them; price, storage and support are not, and the spread between cheapest and dearest is roughly double.

PLATFORM

AMD Ryzen AI Max+ (Strix Halo)

Unified-memory APUs that let a mid-range system hold models that would not fit in discrete VRAM, with most of the pool assignable to the GPU. Dozens of machines ship it; Framework Desktop is the most open and repairable.Memory is soldered, so buy the capacity you want up front. ROCm tooling still trails CUDA.

PLATFORM

Apple Silicon (Mac Studio, Mac mini)

Unified memory makes large-model inference practical on a desktop that fits under a monitor. The choice across the Mac line is capacity and bandwidth, not a different platform.

PLATFORM

Turns one always-on box into several isolated hosts, each running its own agent stack, with a whole GPU handed to whichever one needs it. Passing a consumer card through works; splitting one card across machines does not — that needs datacenter hardware and a licence.

07 REMEMBER

Agent Memory

An Agent That Forgets Between Sessions Is A Demo, Not A Tool. This is the shelf where we have the most at stake: some of these we integrate as optional add-ons, and some are alternatives to what we make. Both are marked. Judge them yourself.

What UMS Can Plug Into — optional add-ons, not requirements

Graphiti

A knowledge-graph memory layer where every fact carries a validity period, so a changed fact closes the old one instead of overwriting it. Ships an MCP server. UMS can install it as an opt-in graph layer; nothing in the core requires it.

INTEGRATEDApache-2.0LOCALMCP SERVER

Kuzu

An embedded graph database — roughly what SQLite is for relational data — which is what made a local graph backend practical with no server to administer. It is the default backend for the Graphiti add-on above, which also supports several others.Upstream is archived: the team was acquired and the repo is read-only after a final release. Existing versions still work, and a community fork continues the line.

INTEGRATEDMITLOCAL

Graphify

Builds a queryable symbol graph of a codebase — definitions, references and call sites across thirty-six languages — so an agent can ask where a function is used instead of grepping for it. One of the opt-in UMS add-ons.The PyPI package is graphifyy, with two y's. The single-y name is an unrelated package.

INTEGRATEDApache-2.0

LLMLingua

Prompt compression that shortens context without discarding the parts a model actually needs. Available as an opt-in UMS add-on.Quiet for the better part of a year — usable, but not actively developed.

INTEGRATEDMIT

Obsidian

A local markdown vault with wiki-links and a graph view. UMS memory files are written to be vault-compatible, so you can read your agent's memory in an ordinary editor — whether or not you ever open Obsidian.

INTEGRATEDLOCAL

10 CONSTRAIN

Security & Sandboxing

Two Directions Of Risk. An agent with tool access is a process that can delete things — and it is also a way in: a poisoned skill, an injected instruction hidden in a web page, an MCP server you did not read. This shelf covers both what an agent might do to you and what someone might do through it.

Guardrails & Permissions

nono

Confines a CLI agent using the operating system's own sandboxing — Landlock, Seatbelt, WSL2 — so access is checked by the kernel rather than inside the agent's process. Ships profiles for Claude Code and OpenClaw.

OVERLAPSApache-2.0LOCAL

cc-safety-net

A pre-tool hook blocking destructive git and filesystem commands across a dozen agent CLIs. It does not enforce filesystem permissions, inspect network traffic, or contain a process — the authors say so plainly.

OVERLAPSMIT

Guardrails AI

Validates model output against declared rules before it reaches your code, and the maintained answer in a category where several well-known projects have been archived.

Apache-2.0
Sandboxed Execution

E2B

Runs model-generated code inside microVMs, so the isolation boundary is hardware virtualization rather than a shared kernel.

Apache-2.0HOSTED

OpenSandbox

A self-hostable sandbox runtime with pluggable isolation behind one API, and signed release images.

Apache-2.0SELF-HOST

Docker MCP Toolkit

Runs MCP servers inside containers with scoped secrets, which matters because an MCP server is code you are running with your credentials.

LOCALMCP RUNTIME
Red-Teaming & Supply Chain

garak

NVIDIA's scanner for probing a model with known attack patterns — prompt injection, jailbreaks, data leakage — and reporting what got through.

11 IMPROVE

Fine-Tuning & Reinforcement Learning

Running A Model Is Table Stakes. Making One Better At Your Job Is Not. Everything here adapts a model that already exists — from scratch is on Learn. Nearly all of it means a small adapter: full weights cost about sixteen gigabytes of VRAM per billion parameters, which prices out most consumer cards.

Fine-Tuning

Unsloth

Fine-tunes open-weight models with custom kernels that cut training memory enough to work on a single consumer GPU, and exports to GGUF, safetensors or vLLM. It also does full-parameter fine-tuning in the same tool, not only adapters. The bundled Studio interface is separately licensed under a copyleft licence, which matters only if you redistribute it.

Apache-2.0LOCAL

LLaMA-Factory

A fine-tuning front end with both a command line and a web interface, covering a wide range of architectures with no training scripts to write. Switches between full, LoRA and QLoRA training with one config flag, and can use Unsloth underneath.

Apache-2.0LOCAL

DistillKit

Distils a large model down into a smaller one that keeps more of its behaviour than fine-tuning alone would. The realistic middle path when adapting an existing model is not enough but training one from nothing is out of reach.

Apache-2.0
Reinforcement Learning & Environments

OpenPipe ART

Wraps reinforcement learning around agent code you already have: supply a trajectory and a reward instead of rewriting your agent to fit a trainer.

Apache-2.0

Environments Hub

A community catalogue of ready-made reinforcement-learning environments, so you do not build reward-checking infrastructure from scratch. Environments, not weights, are the current bottleneck.

REGISTRY

Tinker

A hosted API that runs post-training on someone else's hardware while you write the training loop. The trade is explicit: you give up owning the machine, in exchange for not needing one.

On Our Bench — Testing Next

Two projects attacking the same wall from opposite ends: the model you want is bigger than the machine you have. One squeezes a larger model onto a single box; the other pools several boxes into one. We are watching both closely and want to test them.

  • Colibri — offloads to SSD rather than treating VRAM as the ceiling, so the size of model you can load stops being fixed by the card you own. The trade is speed: at the extreme it is measured in seconds per token, which makes it a can-it-run-at-all tool rather than an interactive one. Needs: a third-party reproduction on a 12 GB card, and enough of a track record to trust the project is not a spike.
  • exo — pools several machines into a single inference cluster, so spare hardware adds up instead of sitting idle. Needs: an official CUDA path — its README still says Linux runs on CPU only, with first-class acceleration on Apple Silicon.
  • TurboQuant — Google's KV-cache quantization: about three bits per value, six times less cache memory, and no calibration step. If it lands, how much context fits on one consumer card changes materially. Needs an upstream merge: Google published no code, llama.cpp has an open discussion and five competing forks, vLLM a feature request. Early forks trade the memory back for speed — one Metal run measured generation eight times slower than q8_0 at long context.
  • MemU — plain-markdown agent memory, philosophically the closest thing to what we build. Needs: a longer track record; it has only been public since early 2026.
  • k3s — one control plane instead of three separately managed hosts. Needs a fleet that has actually outgrown Compose.
  • Microsoft BitNet — native 1-bit models rather than post-hoc quantization. Needs a real trained model above 7B.
  • container-use — a container and a git branch per agent. Needs a stable release; it self-describes as experimental.

Checked And Rejected

Candidates we looked at and did not list. Going read-only is not on its own a reason — what matters is whether there is a maintained path forward.

  • Daytona — core development moved to a private codebase; the public repo will get no further updates. It still looks active at a glance.
  • LLM Guard — archived, along with its models. Guardrails AI is the maintained alternative.
  • GitHub Models — retired. Still listed as free across many directories.
  • PlayHT — API sunset after acquisition; the domains no longer resolve.
  • Piper — the original repo was archived and the maintained fork changed licence, which complicates bundling.
  • Automatic1111 — no meaningful activity in months; superseded in practice.

02 ORCHESTRATE

Multi-Step & Multi-Agent

One agent turn is easy. What runs a hundred of them, in order, without losing state? This is the most crowded corner of the field, and most builders do not need this layer until they do.

Graph & Contract-First

LangGraph

Graph-based orchestration where durable execution, streaming, human-in-the-loop and memory are runtime guarantees rather than things you bolt on. The default pick if you want explicit control over state.

MITSELF-HOST

PydanticAI

Type contracts rather than a graph: you define what each step must return and the framework holds the model to it. The lighter option if a graph DSL feels like ceremony.

MITSELF-HOST

LlamaIndex Workflows

Event-driven orchestration from the LlamaIndex team, at its best when the pipeline is document- and retrieval-heavy rather than general-purpose.

MIT
Role-Based & Interoperability-First

CrewAI

Models a workflow as a crew of role-playing agents with assigned tasks. The most widely adopted framework in this style, and the fastest way to see a multi-agent system working.

MIT

AG2

The community continuation of AutoGen, with native MCP and agent-to-agent protocol support. The pick when you care most about talking to other systems.

Apache-2.0MCP CLIENT

Mastra

A TypeScript-native agent framework, for when the rest of the project is already JavaScript and a Python orchestrator would be the odd one out.

The shortest path from nothing to a model running on your own machine. If you would rather click than type, the desktop apps that do the same job are on Interact.

The engine underneath most local LLM tooling. Its mixture-of-experts offload options let a large model run on one consumer GPU plus system RAM.

MITLOCAL

MITLOCAL

04 METAL

Hardware & Vendor Platforms

What are you running it on? Entries name the platform, not one vendor's box, because the same silicon usually ships in several.

Platforms

NVIDIA GB10 (DGX Spark platform)

A desk-side class of machine with unified memory, for running and fine-tuning large models locally without a rack. NVIDIA's own DGX Spark is one of several systems on this chip. Acer, ASUS, Dell, GIGABYTE, HP, Lenovo and MSI ship the rest.The chip is identical across all of them; memory size, price, storage and support are not.

PLATFORMLOCAL

AMD Ryzen AI Max+ (Strix Halo)

Unified-memory APUs that let a mid-range system hold models that would not fit in discrete VRAM, with most of the pool assignable to the GPU. Many machines ship it; Framework Desktop is the most open and repairable.Memory is soldered, so buy the capacity you want up front. ROCm tooling still trails CUDA.

PLATFORMLOCAL

Apple Silicon (Mac Studio, Mac mini)

Unified memory makes large-model inference practical on a desktop that fits under a monitor. The choice across the Mac line is capacity and bandwidth, not a different platform.

PLATFORMLOCAL

NVIDIA DGX Station

748 GB of coherent memory, models up to a trillion parameters. NVIDIA supplies the board and the OEMs build the machine.

07 REMEMBER

Agent Memory

An agent that forgets between sessions is a demo, not a tool. This is the shelf where we have the most at stake: some of these we integrate as optional add-ons, and some are alternatives to what we make. Both are marked. Judge them yourself.

What UMS Can Plug Into

Optional add-ons set up third-party tools, and some have known problems in the current release.

Graphiti

A knowledge-graph memory layer where every fact carries a validity period, so a changed fact closes the old one instead of overwriting it. Ships an MCP server. A working UMS add-on for it is planned; nothing in the core requires it.

INTEGRATEDApache-2.0LOCALMCP SERVER

Kuzu

An embedded graph database (roughly what SQLite is for relational data), which is what made a local graph backend practical with no server to administer. UMS's Graphiti add-on recommends it; Graphiti also supports several others.Upstream is archived: Apple told the EU in October 2025 that it would buy the company, and the repo is read-only after a final release. Existing versions still work.

INTEGRATEDMITLOCAL

Graphify

Builds a queryable symbol graph of a codebase, with definitions, references and call sites, so an agent can ask where a function is used instead of grepping for it.The PyPI package is graphifyy, with two y's. Other graphify names on PyPI are not affiliated.

INTEGRATEDApache-2.0

Obsidian

A local markdown vault with wiki-links and a graph view. UMS memory files are written to be vault-compatible, so you can read your agent's memory in an ordinary editor, whether or not you ever open Obsidian.

10 CONSTRAIN

Security & Sandboxing

Two directions of risk. An agent with tool access is a process that can delete things, and it is also a way in: a poisoned skill, an injected instruction hidden in a web page, an MCP server you did not read.

Confines a CLI agent using the operating system's own sandboxing so access is checked by the kernel rather than inside the agent's process. Ships profiles for Claude Code and OpenClaw.

OVERLAPSApache-2.0LOCAL

A pre-tool hook blocking destructive commands and secret reads. It does not enforce filesystem permissions, inspect network traffic, or contain a process. The authors say so plainly.

OVERLAPSMIT

OVERLAPSApache-2.0

11 IMPROVE

Fine-Tuning & Reinforcement Learning

Running a model is table stakes. Making one better at your job is not. Everything here adapts a model that already exists (from scratch is on Learn). Nearly all of it means a small adapter: full weights cost about sixteen gigabytes of VRAM per billion parameters, which prices out most consumer cards.

Fine-Tuning

Unsloth

Fine-tunes open-weight models with custom kernels that cut training memory enough to work on a single consumer GPU, and exports to GGUF, safetensors or vLLM. It also does full-parameter fine-tuning in the same tool, not only adapters. The bundled Studio interface is separately licensed under a copyleft licence.

Apache-2.0LOCAL

LLaMA-Factory

A fine-tuning front end with both a command line and a web interface, covering a wide range of architectures with no training scripts to write. Switches between full, LoRA and QLoRA training with one config flag, and can use Unsloth underneath.

Apache-2.0LOCAL

DistillKit

Distils a large model down into a smaller one that keeps more of its behaviour than fine-tuning alone would. The realistic middle path when adapting an existing model is not enough but training one from nothing is out of reach.

Apache-2.0
Reinforcement Learning & Environments

OpenPipe ART

Wraps reinforcement learning around agent code you already have: supply a trajectory and a reward instead of rewriting your agent to fit a trainer.

Apache-2.0

Environments Hub

A community catalogue of ready-made reinforcement-learning environments, so you do not build reward-checking infrastructure from scratch. Environments, not weights, are the current bottleneck.

REGISTRY

Tinker

A hosted API that runs post-training on someone else's hardware while you write the training loop. The trade is explicit: you give up owning the machine, in exchange for not needing one.

Off The Arc: Domain Shelves
◆ DOMAIN

Biotech & Life Sciences

A domain shelf, not a lifecycle stage, kept because it is the domain we know best. Priority: tools that keep genomic data on your own machine.

ClawBio

Bioinformatics skills (pharmacogenomics, variant interpretation, single-cell analysis) running locally on OpenClaw. Its igv-validator skill checks variant calls from your VCF against the reads in your BAM and, with IGV installed, saves a screenshot of each one.Some skills, including the variant annotation ones, send your variants to public services such as Ensembl. The project's data-handling page lists each one and what it sends. igv-validator is built for tumor (somatic) calls and is not yet in a tagged release (November 2026).

MIT coreLOCAL

IGV (Integrative Genomics Viewer)

A desktop genome viewer for checking the BAM, CRAM and VCF files your pipeline produces.By default it accepts commands on port 60151 with no password, from other machines too unless a firewall blocks them; you can turn this off in View > Preferences > Advanced. Its BLAT menu items send the selected sequence to UCSC.

MITLOCAL

igv-reports

The IGV team's command-line tool that turns a VCF and its BAM files into one HTML page with an IGV view at every variant, so calls can be reviewed without opening IGV. An assistant that can run commands can build these pages for you.Use version 1.17.0 or later with a local reference (--fasta); with --genome hg38 it reads the region around each site from UCSC while it builds the page. The page holds read data and sample names, so handle it like the BAM.

MIT

BAMCP

An MCP server that shows the reads behind a variant in a viewer inside the chat, with read evidence and artifact flags for candidate calls or the calls in your VCF.Its ClinVar and gnomAD lookups are on by default and send the variant to NCBI or gnomAD when they run; set BAMCP_CLINVAR_ENABLED and BAMCP_GNOMAD_ENABLED to false for private data. In alpha (November 2026): install from the GitHub main branch and use the default stdio mode.

MITMCP SERVER

NVIDIA BioNeMo Recipes

Worked LoRA fine-tuning recipes for biological foundation models such as ESM2 and Evo2, written to run on a single workstation GPU.

Apache-2.0

BIO26 Healthcare Special Address

NVIDIA's Kimberly Powell at the BIO International Convention, on the BioNeMo Agent Toolkit and the shift from AI that suggests science to AI that runs it.

A full pretrain-to-chat pipeline in one readable codebase. The reference run wants a rented multi-GPU node for about an hour and a half; a single 24 GB card will do it slowly, and a mid-range consumer card sits below what the default configuration expects.

microgpt

Two hundred lines of dependency-free Python that train and run a tiny model in about a minute on a laptop CPU. Not a model you would use for anything, but it is the whole algorithm, short enough to read start to finish.

A full-semester course where you implement tokenization, attention and a distributed training loop by hand rather than calling a library. Free to watch; doing the assignments yourself runs up real rented-GPU bills.

Hugging Face's account of what actually went wrong training a small model, including a run they restarted after burning through a trillion tokens. Reads like a field report rather than a paper.

PyTorch

The framework nearly everything else on this page already runs on. Its own tutorials walk through a training loop starting from a blank module, which is the place to learn what is actually happening before reaching for something higher-level.

TensorFlow & Keras

The other lineage, and still the common answer for edge and production serving. Keras 3 runs on JAX, TensorFlow or PyTorch, so the same model code can be a PyTorch module or a TensorFlow SavedModel. The API outlives the framework choice.Pick the backend before importing Keras; it cannot be swapped afterwards. Legacy tf.keras now lives in its own repository.

On Our Bench: Testing Next

Three projects attacking the same wall from two ends: the model you want is bigger than the machine you have. Two squeeze a larger model onto a single box by reading weights from disk as they go; the third pools several boxes into one.

  • Colibri: offloads to SSD rather than treating VRAM as the ceiling, so the size of model you can load stops being fixed by the card you own. The trade is speed: at the extreme it is measured in seconds per token, which makes it a can-it-run-at-all tool rather than an interactive one. Its own setup asks for at least 8 GB of RAM for the smallest model, and from 16 GB for the large ones it streams from disk; a graphics card is optional.
  • AirLLM: runs models larger than the GPU by streaming each layer from disk onto the card just before it is needed and dropping it straight after. The third-party runs we know of took many seconds per token, and by default it lets a model repo run its own code, so load only models you trust. Needs: an openly published third-party run of an unquantized 70B model on a 4 GB card, with its hardware and timings.
  • exo: pools several machines into a single inference cluster, so spare hardware adds up instead of sitting idle. Needs: a README that stands behind its CUDA path. Its install step lists CUDA extras, but its README still says Linux runs on CPU only.
  • TurboQuant: Google's KV-cache quantization, with about three bits per value, six times less cache memory, and no calibration step. Needs: a TurboQuant cache type merged into llama.cpp.
  • MemU: agent memory, philosophically the closest thing to what we build. Needs: a longer track record.
  • k3s: one control plane instead of three separately managed hosts. Needs a fleet that has actually outgrown Compose.
  • Microsoft BitNet: native 1-bit models rather than post-hoc quantization. Needs a real trained model above 7B.
  • container-use: a container and a git branch per agent. Needs a stable release; it self-describes as experimental.

Checked and Rejected

Candidates we looked at and did not list. Going read-only is not on its own a reason; what matters is whether there is a maintained path forward.

  • LiteLLM: malware that steals credentials shipped in its published releases twice in 2026, in two PyPI releases on 24 March and in version 1.107.0 on PyPI and its official Docker images on 21 October. Both were pulled within hours. The line between its MIT core and its commercial enterprise code is also publicly disputed. Removed from the list on 2026-10-22.
  • LabClaw: most of its skills are copies of K-Dense's and ToolUniverse's; the K-Dense copies omit the scripts and reference files they tell an agent to open, and the repository has no licence file. The originals are still maintained.
  • LLM Guard: archived, along with its models, and no fork has taken its place.
  • GitHub Models: retired. Still listed as free across many directories.
  • PlayHT: shut down after acquisition.
  • Piper: the original repo was archived and the maintained fork changed licence, which complicates bundling.
  • Automatic1111: no meaningful activity in months; superseded in practice.
